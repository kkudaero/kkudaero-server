# 0007. 시작 체크리스트

## 배경

1단계 기능인 시작 체크리스트를 만든다. 단계는 `docs/PRODUCT.md`에 정해져 있다: 사업자등록, 통신판매업 신고, 관세청 전자상거래업자부호, 스마트스토어 해외상품 판매권한, 배대지. 단계별 안내 본문은 아직 검수받지 않았다.

## 결정

- 단계의 순서와 이름은 `ChecklistStep` enum 한곳에 둔다. DB에는 단계 목록을 저장하지 않는다.
- 셀러가 완료한 단계만 `checklist_completions` 테이블에 행으로 저장한다. 행이 있으면 완료이고, 되돌리면 행을 지운다. 완료 시각은 행을 만든 시각이다.
- `GET /api/v1/checklist-steps`는 다섯 단계를 순서대로 주고 내 완료 여부와 완료 시각을 붙인다.
- `PATCH /api/v1/checklist-steps/{step}`은 단계를 완료로 표시하거나 되돌린다. 같은 요청을 다시 보내도 결과가 같고, 이미 완료한 단계를 다시 완료로 표시해도 완료 시각이 바뀌지 않는다.
- 순서를 강제하지 않는다.
- 응답에는 단계 이름만 담는다. 안내 본문과 공식 링크는 넣지 않는다.

## 이유

- 단계는 다섯 개로 고정돼 있고 운영 중에 바꿀 일이 드물다. 코드에 두면 마이그레이션 없이 순서와 이름을 한곳에서 고칠 수 있다.
- 이미 사업자등록을 마친 셀러는 뒤 단계부터 표시할 수 있어야 한다.
- 검수받지 않은 안내를 서버가 내보내면 틀린 내용이 공식 자료처럼 보인다.

## 버린 대안

- 단계 목록을 DB 테이블로 관리: 관리 화면이 없어 지금은 얻는 것이 없다. 안내 본문을 운영 중에 고쳐야 하게 되면 다시 검토한다.
- 가입할 때 다섯 행을 미리 만들기: 단계가 늘면 기존 셀러의 행을 채우는 작업이 필요하다.
- 한 번에 여러 단계를 바꾸는 API: 화면에서 한 단계씩 누르므로 필요하지 않다.

## 아직 정하지 않은 것

- 단계별 안내 본문, 공식 자료 링크, 준비물은 검수받은 내용이 준비되면 추가한다.
- 같은 단계의 완료 요청이 동시에 두 번 들어오면 뒤 요청이 유일 제약에 걸려 500으로 실패할 수 있다. 저장된 결과는 올바르고, 다시 요청하면 성공한다.
- 단계를 지우거나 이름을 바꿀 때 이미 저장된 완료 기록을 어떻게 옮길지 정하지 않았다.
