# 0009. 셀러 탈퇴와 개인정보 삭제

## 배경

셀러가 탈퇴하면 그 셀러와 고객의 개인정보를 삭제해야 한다(AGENTS.md). 주문에 수취인 이름과 개인통관고유부호가 저장되기 시작했는데 지울 방법이 없었다. 인증 결정([0001](0001-seller-authentication.md))에서 탈퇴와 탈퇴한 셀러의 남은 토큰 처리를 미뤄 두었다.

## 결정

- `POST /api/v1/sellers/me/withdrawal`에 현재 비밀번호를 보내면 탈퇴한다. 비밀번호가 틀리면 403이다.
- 탈퇴하면 알림, 체크리스트 완료 기록, 주문, 셀러 계정을 한 트랜잭션에서 실제로 지운다. 유예 기간과 복구는 없다.
- 삭제는 `SellerService`가 테이블마다 명시적으로 한다. 셀러를 참조하는 외래 키에는 `ON DELETE CASCADE`를 걸지 않는다.
- 토큰을 검증할 때 셀러가 있는지 확인한다. 탈퇴한 셀러의 토큰은 만료 전이라도 401이다.
- 같은 이메일로 바로 다시 가입할 수 있다. 이전 데이터는 이어지지 않는다.

## 이유

- 토큰만으로 탈퇴할 수 있으면 탈취된 토큰이나 실수 한 번으로 모든 데이터가 사라진다.
- 개인정보는 필요가 없어지면 바로 지운다. 유료 결제가 없어 법으로 보관해야 하는 거래 기록이 아직 없다.
- 명시적으로 지우면, 셀러 데이터를 담는 테이블을 새로 만들고 탈퇴 처리에 넣는 것을 잊었을 때 외래 키 위반으로 탈퇴가 실패한다. 개인정보가 조용히 남는 것보다 실패가 드러나는 편이 낫다.
- 탈퇴한 셀러의 토큰을 그대로 두면 없는 셀러 ID로 주문을 등록하려다 500이 난다.

## 버린 대안

- `DELETE /api/v1/sellers/me`: 비밀번호를 본문으로 받아야 하는데, DELETE 본문은 클라이언트와 타입 생성 도구에 따라 지원이 다르다.
- 외래 키 `ON DELETE CASCADE`: 코드가 짧아지지만 무엇이 지워지는지 코드에 드러나지 않는다.
- 삭제 표시만 하고 일정 기간 뒤 삭제: 복구 요구가 생기면 다시 검토한다.
- 토큰 차단 목록: 요청마다 셀러가 있는지 확인하는 것으로 충분하다.

## 영향

- 인증이 필요한 요청마다 셀러 존재 확인 조회가 한 번 늘어난다.

## 아직 정하지 않은 것

- 3단계 유료화 뒤 법정 보관 의무가 있는 거래 기록을 어떻게 남길지
- 탈퇴 사유 수집, 탈퇴 확인 메일
- 탈퇴와 통관 자동 조회가 같은 순간에 겹치면 그 주문의 상태 저장이 실패할 수 있다. 실패는 로그만 남기고 넘어간다.
