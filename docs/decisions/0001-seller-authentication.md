# 0001. 셀러 인증: 이메일 + JWT

## 배경

모든 API는 인증된 셀러가 자기 데이터에만 접근해야 한다. 웹이 본체이고 iOS가 보조라서 두 클라이언트가 같은 방식으로 인증할 수 있어야 한다.

## 결정

- 셀러는 이메일과 비밀번호로 가입하고 로그인한다.
- 로그인하면 서버가 HS256으로 서명한 JWT 액세스 토큰을 발급한다. 클라이언트는 `Authorization: Bearer <토큰>`으로 보낸다.
- 토큰의 `sub`는 셀러 ID다. 서버는 세션을 두지 않는다.
- 비밀번호는 BCrypt 해시로만 저장한다. BCrypt의 72바이트 제한 때문에 공백 없는 영문·숫자·특수문자 8~64자로 받는다.
- 서명 키는 `JWT_SECRET`(Base64, 32바이트 이상), 만료 시간은 `JWT_ACCESS_TOKEN_TTL`(기본 1시간)로 받는다.
- 토큰 검증은 Spring Security의 OAuth2 Resource Server(Nimbus)에 맡긴다.

## 이유

- 웹과 iOS가 같은 헤더 방식으로 쓸 수 있고, 서버가 세션 저장소 없이 동작한다.
- 1단계는 네이버 API를 쓰지 않으므로 외부 로그인에 기대지 않는 편이 단순하다.
- 필터를 직접 만들지 않고 검증된 구현을 쓰면 만료·서명 검증 실수를 줄일 수 있다.

## 버린 대안

- 소셜 로그인: 외부 서비스 심사와 설정이 필요하다. 필요해지면 같은 토큰 발급 흐름에 붙인다.
- 서버 세션 + 쿠키: iOS에서 다루기 번거롭고 세션 저장소가 필요하다.

## 아직 정하지 않은 것

- 리프레시 토큰: 지금은 액세스 토큰이 만료되면 다시 로그인한다.
- 이메일 소유 확인, 비밀번호 재설정, 로그인 시도 횟수 제한
- 탈퇴(셀러와 고객 개인정보 삭제)와 탈퇴한 셀러의 남은 토큰 처리
