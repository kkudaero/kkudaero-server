# 0002. 관부가세·마진 예상 계산

## 배경

1단계 기능인 관부가세·마진 예상 계산기를 만든다. 계산은 서버에서만 하고 웹과 iOS는 결과만 받는다. 아직 환율을 조회하는 외부 API 연동과 검수받은 품목별 관세율 표가 없다.

## 결정

- `POST /api/v1/duty-estimates` 하나로 목록통관 판정, 합산과세 경고, 예상 관부가세, 예상 마진을 함께 돌려준다. 결과는 저장하지 않는다.
- 환율(1엔당 원, 1달러당 원)과 관세율, 판매 수수료율은 셀러가 요청에 넣는다. 응답에 계산에 쓴 환율을 그대로 돌려준다.
- 물품가격은 물품 금액과 일본 내 운임의 합이다. 엔화를 원화로 바꾼 뒤 달러 환율로 나눠 달러로 환산한다.
- 물품가격이 150달러 이하면 관부가세를 0으로 본다. 150달러를 넘으면 초과분이 아니라 전체 금액에 과세한다.
- 과세가격은 물품가격(원)에 국제 배송비를 더한 값이다. 관세는 과세가격 × 관세율, 부가세는 (과세가격 + 관세) × 10%이고 원 미만은 버린다.
- 합산과세 경고는 셀러가 넣은 "같은 날 같은 수취인 이름으로 따로 구매한 물품가격 합계"로 판단한다. 이 건만으로는 150달러 이하인데 합치면 넘을 때만 경고한다.
- 마진은 판매가 − 매입 원가 − 국제 배송비 − 판매 수수료이고, 셀러가 관부가세를 부담한다고 표시하면 예상 세액도 뺀다.
- 150달러 기준과 부가세율은 `DutyPolicy`에만 둔다.
- 로그인한 셀러만 쓸 수 있다.

## 이유

- 환율과 관세율을 서버가 임의로 정하면 틀린 값을 공식 값처럼 보여 주게 된다. 셀러가 확인한 값을 받으면 외부 연동 없이도 계산기를 먼저 쓸 수 있다.
- 주문 데이터가 아직 없어서 서버가 같은 날 구매 건을 스스로 찾을 수 없다. 그래서 합산 대상 금액을 입력으로 받는다.
- 경계값 판정은 나눗셈 반올림의 영향을 받지 않게 원화 금액끼리 비교한다.

## 버린 대안

- 관세청 고시환율 자동 조회: 외부 API 연동과 캐시가 필요하다. `infra/exchange`에 붙일 때 요청의 환율 입력을 선택값으로 바꾼다.
- 품목 카테고리별 관세율 표: 공식 자료로 검수한 값이 준비되면 추가한다.
- 관부가세 계산과 마진 계산을 다른 API로 나누기: 화면 하나에서 함께 보여 주므로 한 번에 계산한다.

## 아직 반영하지 않은 것

- 계산에 쓴 환율의 기준 시각: 셀러가 넣은 값이라 서버가 알 수 없다. 환율을 자동 조회하게 되면 응답에 넣는다.
- 과세운임: 실제 통관은 관세청 운임 기준을 쓸 수 있는데, 지금은 셀러가 넣은 국제 배송비를 그대로 쓴다.
- 목록통관 제외 품목(의약품, 건강기능식품 등), 개별소비세 같은 다른 세금, 소액 세액 면제 규정
- 카드 결제 환율과 통관 환율의 차이: 매입 원가도 요청의 엔화 환율로 계산한다.
